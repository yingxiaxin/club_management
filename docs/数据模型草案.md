## users（登录身份）

| 字段 | 类型 | 说明 |
|------|------|------|
| openid / _openid | string | 小程序用户（查询时两者兼容） |
| role | string | `super_admin` / `admin` / `member` / `guest` |
| displayName | string | 展示名 |
| memberId | string \| null | 绑定的成员档案 |
| createdAt | date | |
| lastLoginAt | date | |

应急账号可不入此表，或单独 `admin_credentials`（仅超管，密码哈希）。  
P0-c：管理端扫码登录校验 `role` 为 `admin` / `super_admin`；亦可将 openid 配在云函数环境变量 `ADMIN_OPENIDS`（首次确认自动建超管）。  

**任命管理员（管理端）**：超管对已关联成员写/改本表 `role`（`member`↔`admin`），`openid` 取自 `members.boundOpenid`；撤销不清除 `memberId`。详见 `docs/任命管理员.md`。不在产品内把人写成 `super_admin`（超管仍靠云库手改 / 白名单 / 应急）。

## activities（活动实例）

| 字段 | 类型 | 说明 |
|------|------|------|
| title | string | |
| type | string | `daily` / `weekly` / `pvp` / `custom`（创建时直接选，无模板表） |
| startSchedule | object | 开始分量：`year` / `month` / `day` / `weekday`(1=周一…7=周日) / `time`(`HH:mm`)，均可空，但至少填一项 |
| endSchedule | object \| null | 结束分量，结构同 start；全空则为 null |
| startAt | date \| null | 当 start 含完整年月日+时间时写入 ISO，供排序/兼容；否则 null |
| endAt | date \| null | 同上 |
| description | string | |
| enableTeam | boolean | |
| reminderCycle | string | `none` / `once` / `daily` / `weekly` / `monthly`；**无开始时间则强制 `none`（不发提醒）** |
| reminderOffsetsMinutes | number[] | 提前量（5/10/15/30/60/120）；默认 10；`none` 时为空数组 |
| status | string | `draft` / `published` / `ongoing` / `ended` / `cancelled` |
| createdBy | string | |
| createdAt / updatedAt | date | |

提醒周期可选性（相对 **开始** 分量）：无时间 → `none`；年月日+时间 → 仅 `once`；日+时间 → `once`/`daily`；周几+时间 → `once`/`weekly`；仅时间 → `daily`。

> 已砍活动模板；云库若残留 `activity_templates` 可忽略。

## activity_rsvps（出席意向）

| 字段 | 类型 | 说明 |
|------|------|------|
| activityId | string | |
| memberId | string | |
| characterName | string | 冗余角色名，便于名单展示（以 members 为准可刷新） |
| status | string | `going` / `maybe` / `decline` |
| createdAt / updatedAt | date | |

文档 id：`{activityId}__{memberId}`（保证一人一活动唯一）。

**读接口补充**：活动详情 `rsvpGroups.*` 项除 `characterName` 外带当前成员 `pathway`（自 `members` 联查，非落库冗余），供途径色展示。队伍详情 `members` / `pendingApplications` 同理带 `pathway`。

## 权限原则

- 客户端直连数据库时：仅开放成员只读自身+公开成员列表所需字段；写操作优先走云函数。
- 管理端写操作一律云函数内校验 `admin` / `super_admin`。
