## 1. 目标与边界

| 方向 | 目标 |
|------|------|
| **出勤看板** | 管理端一屏看今日/本周谁来、哪场缺人；可对已结束场次轻量点名；成员意向/实到可查摘要 |
| **「我的」页** | 小程序二级页聚合「我是谁、报了啥、有啥队、提醒、管理入口」；页标题与导航文案统称「我的」 |

**明确不做**

- 积分 / DKP / 全员出勤排行榜公示  
- 成员自助签到、扫码签到、地理位置  
- 第四 Tab（与「组队不做独立 Tab」一致）  
- **本周请假**（周级开关；与单场 RSVP `decline` 重复，**已砍**）  
- 重做 P2-e 全量队伍总览（今日卡片仅嵌今日相关队伍摘要）  
- 评论、聊天、多俱乐部  

**与现网关系**

- 复用 `activity_rsvps`、`activity_rsvp_snapshots`、`teams` / `team_applications`、`subscriptions`  
- RSVP 语义不变；实到另存 `activity_attendance`  
- 单场请假仍用 RSVP `decline`

## 2. 出勤看板（管理端）

### 2.1 信息架构

新增侧栏页：**出勤看板**（挂在「活动日程」下）。子视图：

| 子视图 | 内容 | 阶段 |
|--------|------|------|
| **今日一屏**（默认） | 上海「今天」有本场的已发布/进行中/今日已结束活动 | board-a |
| **本周概览** | 本周各活动一行：日期、标题、RSVP 三态；已结束且已点名则显示实到人数 | board-a/b ✅ |
| **成员出勤摘要** | 近 4 周（可调）RSVP 次数与意向率 + **实到次数**（含未报名补录）；点行看近 N 场明细 | board-b ✅ |

活动 CRUD 仍在「活动日程」页；看板不承担新建/编辑表单。

**今日活动卡片字段**

- 标题、本场时间、阶段（未开始 / 进行中 / 已结束）  
- RSVP：going / maybe / decline 人数  
- 若 `enableTeam`：招募中队伍数、差人数合计（现有 teams 列表按 `activityId` + 今日筛，不做 P2-e）  
- 点击 → 本场名单 +（board-b 可点名时）实到编辑  

### 2.2 实到（轻量点名）· board-b

| 项 | 约定 |
|----|------|
| 谁可写 | `admin` / `super_admin` |
| 何时可编辑 | 本场**已结束**后可保存计入统计；**进行中**允许预勾，统计默认只计「已结束且已保存」 |
| 结束时刻 | 与 RSVP 锁定同一套规则（见 `P1-c` / 功能说明书 §3.3） |
| 打开默认 | 已有 `activity_attendance` → 回显；否则预勾全部 `going`，maybe/decline 不勾但可勾 |
| 未报名 | 可从成员列表**补录**进实到（不强制先填 RSVP）；名单单独「未报名补录」区 |
| 存储 | 集合 `activity_attendance`，**不改** RSVP |
| 文档 id | `{activityId}__{occurrenceDateKey}` |
| 场次日 | 与导出/快照一致；一次性活动无显式场次日时用开始日（上海）`YYYY-MM-DD` |
| 换场 | 周期换场**不删**实到；历史点名读写本集合 |

字段见数据模型 `activity_attendance`。

### 2.3 ~~本周请假~~（已砍 · 2026-10-26）

原计划周级运营信号 + `member_week_leave`。与单场 RSVP `decline` 重复，且不自动改 RSVP，价值不足。**不做**；看板不展示请假顶条。集合草案保留标注「已砍勿实现」。

### 2.4 统计口径

| 指标 | 口径 |
|------|------|
| **意向出勤率（成员）** | 近 N 个已结束场次中 `status=going` 占比；分母=该成员**有过 RSVP** 的场次数（无 RSVP 不进分母） |
| **实到率（活动）** | `presentMemberIds.length / goingCount`；`goingCount` 为点名保存时的 going 人数；无 going 显示 — |
| 摘要数据源 | 当前 `activity_rsvps`（未换场本场）+ `activity_rsvp_snapshots.rows`；仅有完整场次日的记录 |

导出：首版不强制；可后续在 RSVP CSV 旁加实到列或独立导出。

### 2.5 API 轮廓

管理端（本机/公网 Express，角色校验同现网）：

| 路径 | 阶段 | 说明 |
|------|------|------|
| `GET /api/ops/board/today` | board-a ✅ | 今日一屏（旧路径 `/tonight` 兼容；含 `attendance` 摘要） |
| `GET /api/ops/board/week` | board-a ✅ | 本周概览（含实到列数据） |
| `GET /api/activities/:id/rsvps` | board-a ✅ | 本场名单（分组，含 memberId） |
| `GET/PUT /api/activities/:id/attendance?dateKey=` | board-b ✅ | 实到读写 |
| `GET /api/ops/board/member-stats?weeks=4` | board-b ✅ | 成员出勤摘要 |

具体路径实现时可微调，须与本文语义一致。

## 3. 「我的」页（小程序）

### 3.1 入口与权限

- **入口**：首页会务条**身份区**可点进入本页；右侧「日程」入口可保留。  
- **未绑定**：进页后引导邀请码关联，不展示会务数据。  
- **管理员**：解绑与扫码登录等迁到本页底部「管理」区（与首页能力对齐，避免首页堆叠）。  
- **导航**：`pages/mine/` 为**非 Tab** 二级页；`app.json` 注册 pages，不增加 tabBar 项。

### 3.2 区块（自上而下）

1. **身份卡片**：角色名（途径色）、职位、非凡评分/风尚度摘要、账号角色；「查看档案」→ 自己的成员详情。  
2. **待我处理**（有则显）：我任队长且申请 `pending` 数 → 队伍详情审批。  
3. **我的 RSVP**：分组「进行中/未开始」与「近 14 天已结束」；状态色签；进活动详情改表态（锁规则不变）。  
4. **我的队伍**：我创建的 / 我参加的（进行中优先）。  
5. **提醒**：已订阅活动列表或说明 + 深链活动详情授权；不在此配置俱乐部提前量。  
6. **管理区**（`isAdmin`）：扫码登录、解绑。  

成员端最多展示**自己的**近 N 场 going/decline 计数；**不对全员公示**出勤率。

### 3.3 首版不做

- 第四 Tab  
- 本周请假开关  
- 成员自改评分/途径  
- 「我的踏云」大页（删图仍在作品详情）  
- 全员出勤榜  

### 3.4 memberApi 增量

| action | 说明 |
|--------|------|
| `myDesk` | 只读聚合：身份摘要、待审批数、我的 RSVP、我的队伍摘要、已订阅活动 id 列表 |

敏感写仍走云函数。
