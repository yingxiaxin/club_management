> **状态**：方案甲；**用户已将管理端托管到 Windows 云主机**（2026-10-26）。代码 `SERVE_ADMIN` 已合入。

## 云开发 ≠ 云主机

| 已有（云开发 `cloud1-…`） | 另有（你的云主机） |
|---------------------------|-------------------|
| 云函数 / 云数据库 / 云存储 | SSH 上去装 Node 的那台机 |
| 小程序读写云库 | 本文件部署的管理端 API + 静态页 |

管理端公网仍连**同一云库**（把本机 `.env` 里的 `CLOUDBASE_*` 拷到服务器）。

---

## 架构（方案甲）

```
浏览器 ──HTTPS──► Nginx(443) ──► Node(127.0.0.1:3789)
                                    ├─ /api/*     业务 API
                                    └─ 其它       admin/dist 静态页
```

本机开发不变：`admin` Vite `5173` 代理 `/api` → `3789`；**不要**在本机开 `SERVE_ADMIN`（除非自测生产模式）。

## 你现在按这个做（👤）

### 0. 准备信息

- [ ] 云主机公网 IP、系统（**Linux 或 Windows Server 均可**）  
- [ ] 远程桌面 / SSH；防火墙与安全组放行 **3389（若用 RDP）/ 80 / 443**；冒烟测 API 时临时放行 **3789**  
- [ ] （建议）已备案域名，DNS **A 记录** 指到主机 IP  

无域名时可先用 `http://IP:3789` 冒烟（仅测试；正式务必 HTTPS + 域名）。

### 1. 本机打包前端

在开发机：

```bash
cd admin
npm ci
npm run build
```

得到 `admin/dist/`（也可由 Agent 代打）。

### 2. 把代码弄上服务器

**可以整仓拷贝**（U 盘 / 远程桌面复制 / `git clone`），推荐目录例如：

- Windows：`C:\club_management\`  
- Linux：`/opt/club_management/`

服务器上至少要有：

- `admin/dist/`（已构建）  
- `cloud/dev-server/`（`package.json` + `src/` 等）  

注意：

| 要拷 | 不要拷 / 慎拷 |
|------|----------------|
| 源码、`admin/dist` | 把本机 `.env` **明文发到聊天**；可在服务器上**新建** `.env` 再粘贴内容 |
| | 可选：不拷 `node_modules`，在服务器上再 `npm ci`（更干净） |
| | 若整包拷 `node_modules`：须 **同系统**（Win→Win 可以；Lin→Win 不行） |

Linux 样例见下文「Linux 补充」。**Windows 见下一节。**

### 2b. Windows 服务器（你当前环境）

1. 安装 **Node.js 18 LTS 或 20**（官网 MSI），装完 `node -v` / `npm -v` 可用。  
2. 拷贝仓库到例如 `C:\club_management\`（含已打好的 `admin\dist`）。  
3. 在 `C:\club_management\cloud\dev-server\` **新建** `.env`（内容见下「生产 .env」）。  
4. 管理员 PowerShell：

```powershell
cd C:\club_management\cloud\dev-server
npm ci --omit=dev
# 若 npm ci 因锁文件失败，可改用：npm install --omit=dev

$env:HOST="0.0.0.0"
# 或把 HOST/SERVE_ADMIN 写进 .env 后直接：
node src\index.js
```

5. 本机浏览器打开 `http://公网IP:3789/`，应出登录页。控制台应有 `SERVE_ADMIN=on`。  
6. **常驻**：不要长期开着远程桌面窗口跑。任选：  
   - [pm2](https://pm2.keymetrics.io/)：`npm i -g pm2` → `pm2 start src/index.js --name club-admin` → `pm2 save` + 按文档做 Windows 开机启动；或  
   - [NSSM](https://nssm.cc/) 把 `node src\index.js` 注册为 Windows 服务（工作目录指到 `dev-server`）。  
7. **HTTPS**（正式建议）：  
   - 有域名：IIS 反代到 `http://127.0.0.1:3789`，或装 Caddy/Nginx for Windows 做证书；`.env` 里 `HOST=127.0.0.1`，安全组只开 80/443。  
   - 先内测：可暂时只开 3789 + HTTP（勿对公网长期裸奔）。  

Linux 的 systemd / Nginx 样例在 `cloud/dev-server/deploy/`，**Windows 不用那些文件**。

### 3. 生产 `.env`（两系统通用）

在 `cloud/dev-server/.env` 写入（从本机抄密钥，**勿提交 Git**）：

```env
DATA_BACKEND=cloud
CLOUDBASE_ENV=cloud1-d6gjqx2kd2f3765f4
CLOUDBASE_SECRET_ID=...
CLOUDBASE_SECRET_KEY=...
WECHAT_APPID=wx0a3fc7a2aee9f66f
WECHAT_APP_SECRET=...
CLOUD_QR_ENV_VERSION=release

HOST=0.0.0.0
PORT=3789
SERVE_ADMIN=1
# 有域名 HTTPS 后：
# ADMIN_CORS_ORIGIN=https://admin.你的域名

EMERGENCY_SUPER_USERNAME=...
EMERGENCY_SUPER_PASSWORD=...
```

### 4. Linux 补充（若以后换 Linux 机）

```bash
cd /opt/club_management/cloud/dev-server
npm ci --omit=dev
node src/index.js
```

常驻用 `deploy/club-admin.service.example`；HTTPS 用 `deploy/nginx.example.conf` + certbot。前面有 Nginx 时建议 `HOST=127.0.0.1`。

### 5. 与小程序正式版对齐

- [ ] 小程序已发布**正式版**（否则 `release` 码难扫）  
- [ ] `.env`：`CLOUD_QR_ENV_VERSION=release`  
- [ ] 管理端提醒设置：下发环境 **`formal`**  
- [ ] 浏览器打开公网地址 → 扫码登录 → 改一条无害数据

## 代码开关（已实现）

| 变量 | 作用 |
|------|------|
| `SERVE_ADMIN=1` | Express 托管 `admin/dist`，非 `/api` 回落 `index.html` |
| `ADMIN_DIST` | 自定义 dist 路径（相对 `cloud/dev-server`） |
| `HOST` / `PORT` | 监听地址 |
| `ADMIN_CORS_ORIGIN` | 公网允许的 Origin（逗号分隔） |
| `/api/auth` | 简易每分钟限流 |

本地开发：不设 `SERVE_ADMIN`，保持 Vite + 代理即可。
