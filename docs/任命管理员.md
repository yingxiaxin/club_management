# 任命 / 撤销管理员（管理端）

> **已实现（本机 API + 管理端成员列表）**。权限以 `docs/功能说明书.md` §2 为准：仅 **超管** 可指定/撤销管理员。  
> 实现：`cloud/dev-server/src/cloudUsers.js`、`POST .../grant-admin|revoke-admin`、`MembersView` 身份列。

## 目标

在 PC 管理端把**已关联微信**的成员任命为 `admin`，使其能扫码登录管理后台；也可撤销，降回普通成员身份。  
**不做**：在管理端把人提成 `super_admin`；普通 `admin` 互相任命；无微信绑定的成员任命。

## 角色规则（硬性）

| 操作者 | 可任命 | 可撤销 | 说明 |
|--------|--------|--------|------|
| `super_admin` | 成员 → `admin` | `admin` → `member`（仍绑成员则） | 唯一有权操作者 |
| `admin` | — | — | 不可任命/撤销任何人 |
| `member` / `guest` | — | — | 无管理端权限 |

补充约束：

1. **目标须已关联微信**：`members.boundOpenid` 非空；否则提示「请先让该成员用邀请码关联微信」。  
2. **只写 `users.role`**：任命不新建成员档案；撤销不解除 `boundOpenid` / `memberId`（仍可看小程序）。  
3. **不碰超管**：列表上对 `super_admin` 不显示「取消管理员」；不可把某人任命为 `super_admin`（超管仍用手改云库 / `ADMIN_OPENIDS` / 应急流程）。  
4. **不可撤销自己的超管身份**（本功能无此按钮）。  
5. 若目标 openid 尚无 `users` 行：任命时 **创建** `{ openid, role: 'admin', memberId, displayName: 角色名 }`。  
6. 若目标已是 `admin`：任命按钮灰掉或提示「已是管理员」。  
7. 撤销后：`role = member`（有 `memberId`）或 `guest`（无绑定）；小程序「管理入口」随 `whoami.isAdmin` 消失。

## 用户流程

### 任命

1. 超管用应急账号或扫码进入管理端。  
2. **成员列表**找到目标 → 操作列「任命为管理员」。  
3. 二次确认文案示例：「将「角色名」任命为管理员后，其绑定微信可扫码登录管理后台。是否继续？」  
4. 成功 → Toast；该行身份列变为「管理员」。  
5. 对方打开小程序 → 首页「我的身份」可展开管理工具 → PC 扫码登录可进后台。

### 撤销

1. 成员列表对 `admin` 显示「取消管理员」。  
2. 确认：「取消后将无法登录管理后台，小程序成员能力保留。」  
3. 成功 → 身份列变「成员」。

## 管理端 UI

入口：**成员列表**（`admin/src/views/MembersView.vue`），不新开顶栏路由（可后续加「管理员一览」筛选）。

建议改动：

| 项 | 说明 |
|----|------|
| 身份列 | 展示后台角色：`超管` / `管理员` / `成员` / `未关联`（无 boundOpenid） |
| 操作 | 超管会话才显示任命/撤销；`admin` 会话不显示 |
| 筛选（可选） | 身份 = 全部 / 管理员 / 未关联 |

应急账号登录若会话角色为 `super_admin`，同样可操作。

## API（本机 dev-server → 云库 `users`）

建议（路径可微调，语义保持）：

| 方法 | 路径 | 谁可调 | 行为 |
|------|------|--------|------|
| `POST` | `/api/members/:id/grant-admin` | 仅 `super_admin` | 见下 |
| `POST` | `/api/members/:id/revoke-admin` | 仅 `super_admin` | 见下 |
| `GET` | `/api/members`（扩展） | admin+ | 每条附带 `accountRole`：`super_admin` \| `admin` \| `member` \| `null`（未关联或无 users） |

### grant-admin

1. `requireSuperAdmin`。  
2. 读成员；`status !== left`；`boundOpenid` 必有。  
3. 按 openid 查/建 `users`：  
   - 若已是 `super_admin` → 409「该微信已是超管，勿用本功能改」  
   - 若已是 `admin` → 200 幂等或 409「已是管理员」  
   - 否则 `role=admin`，写入 `memberId`、`displayName`  
4. 返回更新后的成员 + `accountRole`。

### revoke-admin

1. `requireSuperAdmin`。  
2. 成员须有 `boundOpenid`；查 `users`。  
3. 若 `role === super_admin` → 403。  
4. 若 `role !== admin` → 幂等成功或提示未任命。  
5. `role = memberId ? 'member' : 'guest'`。  
6. **不要**清 `memberId` / `boundOpenid`。

实现位置建议：

- `cloud/dev-server/src/index.js` 路由  
- `cloud/dev-server/src/cloudMembers.js` 或新建 `cloudUsers.js`（按 openid 更新 role）  
- `admin/src/api/members.ts` + `MembersView.vue`  
- 会话里已有 `user.role` 时，前端用其控制按钮显隐；后端仍必须校验（防伪造）

> 写操作走本机 API + 云库即可（与邀请码审核同模式）。**不必**为任命单独扩 `memberApi`，除非以后要在小程序内自助申请管理员。

## 数据模型

仍用集合 `users`（见 `docs/数据模型草案.md`）：

| 字段 | 任命时 | 撤销时 |
|------|--------|--------|
| `openid` | = `members.boundOpenid` | 不变 |
| `role` | `admin` | `member` 或 `guest` |
| `memberId` | 指向该成员 | **保留** |
| `displayName` | 建议同步角色名 | 可保留 |

无需新集合。可选后续：`roleChangedAt` / `roleChangedBy`（审计进 P3 再做）。

## 验收清单

1. [ ] 超管对**已关联**成员任命 → 云库 `users.role=admin` → 对方扫码可进管理端（需另有已关联普通成员；当前云库仅「美帝」为超管已绑）  
2. [ ] 超管撤销 → `role=member` → 对方扫码被拒；小程序仍可看成员/活动  
3. [x] 未关联成员点任命 → 明确错误，不写库（API 已测）  
4. [x] 普通管理员登录 → 无任命/撤销按钮；直调 API → 403（API 已测；UI 依赖 `session.role`）  
5. [x] 超管行不出现「取消管理员」；不可把人提成超管（API：任命/撤销均拒超管目标）  
6. [ ] 任命后小程序 `whoami.isAdmin=true`，出现「管理入口」  

## 明确不做（本刀）

- 管理端 UI 创建/降级 `super_admin`  
- `admin` 任命其他 `admin`  
- 与游戏内「职位」字段自动同步（职位仍手录；后台 `role` 独立）  
- 操作审计日志（归 P3）  
- P2 组队
