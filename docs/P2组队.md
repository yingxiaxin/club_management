# P2：活动组队 LFG

> **实现约定（定稿）**。产品条文见 `docs/功能说明书.md` §3.5；集合见 `docs/数据模型草案.md`（`teams` / `team_applications`）。  
> **2026-10-23**：正式公开前必做；子阶段见 `docs/开发阶段规划.md`「P2」。  
> **P2-a / P2-b / P2-c / P2-d 已实现**：API + 小程序组队页（含筛选）+ 到点定时；**P2-e** 管理端总览 UI **暂缓**（2026-10-26：必要性不大，放着；API 仍保留）。

## 目标

已入会成员可围绕**已开启组队**的活动：建队招人 → 申请 → 队长审批 → 满员/踢人/转让 → 到点结束招募。  
管理员可在后台总览并必要时强制关闭。

## 不做

- 跨活动共用队伍；无活动挂靠的「野队」
- 语音 / 游戏内自动同步 / 分账
- 按 RSVP 自动入队（RSVP 与组队独立）
- 管理端升降队长以外的成员字段编辑（改评分仍走成员 CRUD）
- 不做管理端总览页以外的成员字段编辑；P2-e 总览 UI **暂缓**（API 已有列表/强制关闭，需要时再点名做页）

## 前置条件

| 条件 | 说明 |
|------|------|
| 活动 `enableTeam === true` | 关则详情不入口；已有队伍只读展示「活动已关闭组队」，禁止新建/申请 |
| 活动状态 | 仅 `published` / `ongoing` 可建队、申请；`draft`/`ended`/`cancelled` 禁止写操作 |
| 本场未结束 | 与 RSVP 相同：按活动**本场结束时间**；已结束不可新建/申请；**周期模板本场结束后系统清空该活动下队伍**（`dissolved`） |
| 操作者 | 须已绑定有效成员（`users.memberId` → `members` 且非 `left`）；与 RSVP 相同 |
| 管理员未绑成员 | 不可建队/申请（无成员档案）；后台强制关闭走管理端会话，不依赖成员绑定 |

## 字段与默认值

与数据模型一致，实现时约定：

| 字段 | 约定 |
|------|------|
| `activityId` | 必填；创建后不可改 |
| `modeName` | 副本/模式，必填非空文本 |
| `startAt` | **绝对时刻**（ISO / Date）；见下节「开打时间」 |
| `maxMembers` | 整数 ≥ 2；队长占 1 席；**创建默认 6**（表单/未传时） |
| `minPowerScore` | 可选；有值则申请时校验 `members.powerScore` |
| `remark` | 可选 |
| `leaderMemberId` | 创建者；须 ∈ `memberIds` |
| `memberIds` | 含队长；有序数组，队长可固定为 `[0]` 或单独字段为准（**以 `leaderMemberId` 为准**） |
| `status` | `recruiting` / `full` / `paused` / `started` / `dissolved`（旧 `closed` 视同撤销） |

申请表：

| 字段 | 约定 |
|------|------|
| `teamId` + `memberId` | 同一队伍同一成员**至多一条**现行记录（文档 id 建议 `{teamId}__{memberId}`） |
| `message` | 申请附言，可选 |
| `status` | `pending` / `approved` / `rejected` / `cancelled` / `kicked` |

冗余（列表展示用，可读时刷新）：`leaderCharacterName`、成员侧可返回 `characterName` / `powerScore`。

## 开打时间与自动结束（锁定）

功能说明书「活动开始 **或** 队伍开打时间」→ **实现锁定如下**：

1. 队伍自有 **`teams.startAt`（绝对时刻）** 为唯一「到点」依据。  
2. **创建时默认**：若关联活动有 `activities.startAt`（完整年月日+时间已落地），则复制为队伍 `startAt`；队长可改（不可早于「现在」过多约束：允许改到活动前后，产品不拦，仅 UI 提示）。  
3. 若活动**无**绝对 `startAt`（仅有星期/时间分量）：创建时 `startAt` 可空，**队长创建表单必填开打时间**（或选「不设到点」→ `startAt=null`）。  
4. **`startAt` 到达后**：`recruiting` / `full` → **`started`**；拒绝新申请；待审申请一律标 `rejected`（系统理由「已开始」）。  
5. **`startAt == null`**：不跑自动结束；仅队长/管理员 **关闭** → `closed`。  
6. 定时任务（**P2-d ✅**）：独立云函数 **`teamLifecycle`**（触发器 `teamLifecycleTick`，每分钟）→ `memberApi` action `expireTeamsDue`：先扫**一次性**活动本场已结束 → `status=ended` 并 `closeActiveTeamsByActivity`；再扫 `status in (recruiting,full,paused) && startAt <= now` → `started`。**周期活动**不改活动 status。本机可 `POST /api/teams/expire-due`；单队可 `POST /api/teams/:id/mark-started`。

**与活动状态**：活动被管理员标 `ended`/`cancelled`，或一次性活动到点自动 `ended` 时，该活动下招募中队伍 → `dissolved`（`closeTeamsForActivity` / `closeActiveTeamsByActivity`）。周期换场另走 `dissolveAllByActivity`，活动保持已发布。

## 状态机

### 队伍 `teams.status`

```
创建 → recruiting
recruiting ──人数达上限──► full
full ──有人离开且未满──► recruiting
recruiting|full ──startAt 到点──► started
recruiting|full ──关闭招募──► paused ──开启招募──► recruiting|full
recruiting|full|paused ──撤销队伍──► dissolved（列表隐藏）
recruiting|full|paused ──startAt 到点──► started
```

| 状态 | 可申请 | 可审批通过 | 可踢人/转让 | 说明 |
|------|--------|------------|-------------|------|
| `recruiting` | ✓ | ✓ | ✓ | |
| `full` | ✗ | 未满才可通过 | ✓ | 达上限自动进入 |
| `paused` | ✗ | ✗（先开招募） | ✓ | 关闭招募；仍在列表 |
| `started` | ✗ | ✗ | ✗ | 只读 |
| `dissolved` | ✗ | ✗ | ✗ | 撤销；不出现在活动队伍列表 |

满员判定：`memberIds.length >= maxMembers` → `full`；离开后 `< maxMembers` 且原为 `full` → `recruiting`。

### 申请 `team_applications.status`

| 从 → 到 | 谁 | 条件 |
|---------|-----|------|
| （无）→ `pending` | 申请人 | 队伍 `recruiting`；申请人不在任何**本活动**已通过队伍中；无进行中的 `pending`（同队）；评分达标 |
| `pending` → `approved` | 队长 | 未满；通过后写入 `memberIds`；满则队伍→`full` |
| `pending` → `rejected` | 队长或系统（到点） | |
| `pending` → `cancelled` | 申请人 | 撤回 |
| `approved` → `kicked` | 队长踢人 | 同时从 `memberIds` 移除；不可踢队长 |
| `approved` → （退出） | 队员主动退出 | 申请记录可标 `cancelled` 或保留 `approved` 并移出 ids——**约定：移出 `memberIds`，申请行改 `cancelled`（主动离队）**；被踢为 `kicked` |
| `rejected` / `cancelled` / `kicked` → `pending` | 申请人再次申请 | 队伍仍 `recruiting` 时允许把同行改回 `pending`（或删建等价） |

队长创建队伍：**不写申请行**；直接 `leaderMemberId` + `memberIds=[自己]`。

## 业务规则（硬性）

1. **一活动一队籍**：同一 `activityId` 下，一名成员最多处于一支队伍的 `memberIds` 中。有队籍则不可再申请本活动其他队。  
2. **同时 pending**：同一成员对同一活动，允许对多队各有一条 `pending`（方便货比三家）；**任一通过**时，自动 `cancelled` 其在本活动其他队的 `pending`。  
3. **评分**：若 `minPowerScore != null` 且 `powerScore < minPowerScore` → 申请 403「评分不足」。  
4. **转让队长**：仅队长；目标须已在 `memberIds`；转让后原队长仍为队员。  
5. **踢人**：不可踢自己；不可踢非队员。  
6. **关闭招募 / 开启招募 / 撤销**：关招募 → `paused`（可再开）；撤销 → `dissolved`（列表隐藏）；关招募时 `pending` → `rejected`。  
7. **关闭组队开关**：活动 `enableTeam` 改为 false 后禁止新建与新申请；已有队伍不删除。  
8. **权限**：队员操作校验「当前用户绑定的 memberId」；队长操作另校验 `leaderMemberId`；管理端强制关闭校验 `admin`/`super_admin`。

## API

### A. 小程序 · `memberApi`（主路径）

`cloud.callFunction({ name: 'memberApi', data: { action, ... } })`  
均需已绑定成员（除只读列表可对已绑定开放；未绑定 403）。

| action | 参数 | 说明 |
|--------|------|------|
| `listTeamsByActivity` | `activityId`；可选 `timeFilter` / `mineFilter`（P2-c） | 本活动队伍；含人数、状态、队长名、是否已申请/已在队 |
| `getTeam` | `teamId` | 详情 + 队员列表 + 我的申请状态；队长额外看 `pending` 列表 |
| `createTeam` | `activityId, modeName, startAt?, maxMembers, minPowerScore?, remark?` | → `recruiting` |
| `updateTeam` | `teamId` + 可改字段 | 仅队长；`recruiting`/`full`；不可改 `activityId`；改 `maxMembers` 若小于当前人数则 400 |
| `applyTeam` | `teamId, message?` | → `pending` |
| `cancelTeamApplication` | `teamId` | 撤回自己的 `pending` |
| `reviewTeamApplication` | `teamId, memberId, decision: approve\|reject` | 仅队长 |
| `kickTeamMember` | `teamId, memberId` | 仅队长 |
| `leaveTeam` | `teamId` | 非队长离队；队长须先转让或关闭 |
| `transferTeamLeader` | `teamId, memberId` | 仅队长 |
| `pauseTeamRecruiting` | `teamId` | 仅队长；→ `paused` |
| `resumeTeamRecruiting` | `teamId` | 仅队长；`paused` → `recruiting`/`full` |
| `dissolveTeam` | `teamId` | 仅队长；→ `dissolved`（列表隐藏） |
| `closeTeam` | `teamId` | 兼容旧名，等同 `dissolveTeam` |
| `listMyTeams` | `filter?` / `mineFilter?: created\|joined`；`timeFilter?: tonight\|week` | P2-c |

只读接口在 `getActivity` 响应中可增加 `teamCount`（P2-b）。

### B. 管理端 · 本机 HTTP（P2-a 可先做强制关闭 + 列表；总览 UI 属 P2-e）

| 方法 | 路径 | 谁 | 行为 |
|------|------|-----|------|
| `GET` | `/api/teams?activityId=&status=` | admin+ | 总览列表 |
| `GET` | `/api/teams/:id` | admin+ | 详情 |
| `POST` | `/api/teams/:id/force-close` | admin+ | → `closed`；pending → rejected |

P2-a **优先**：抽出 `teamsDb.js`（可与云函数共用逻辑），本机用云库后端时直接写云；并实现上表 member 侧 action（本机可用临时 HTTP 包装或直接部署云函数测）。若本机暂无成员 openid 上下文，P2-a 验收以云函数 + 开发者工具为主，管理端三条 HTTP 可先通。

### C. 内部 / 定时（P2-d ✅）

| 名称 | 行为 |
|------|------|
| `teamLifecycle` 定时 | 每分钟 → `memberApi.expireTeamsDue` |
| `expireTeamsDue` | 将到期 `recruiting`/`full`/`paused` → `started`，pending → rejected「已开始」；小程序带 OPENID 调用拒绝 |
| 活动 transition 钩子 | `ended`/`cancelled` → 下属活跃队伍 `dissolved`（管理端已接） |
