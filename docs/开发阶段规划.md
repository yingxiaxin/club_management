# 开发阶段规划

## 总原则

按 **P0 → P1 → 小程序可用化 → 任命管理员 → P2 组队 → 正式公开 → P3** 递进。  
（2026-10-22：P1 后先可用化；**2026-10-23：用户决定 P2 组队提前到正式公开前做完**。）  
每一阶段有可验收产物；正式公开前以 `docs/上线待办.md` 为准勾选环境/密钥项。

技术落地默认：`miniprogram/` + `admin/` + `cloud/`（微信云开发）。

---

## P0 — MVP：成员可录入、可查看

**目标**：管理员维护成员列表；成员打开小程序能看到评分等信息。

**实施顺序（已定：先 PC 可见效果，后小程序）**

| 子阶段 | 内容 | 你能看到的效果 |
|--------|------|----------------|
| **P0-a** | `cloud`：集合约定 + 成员/登录相关云函数（可先 HTTP 供管理端调用） | 接口可用（Postman/控制台） |
| **P0-b** | `admin`：主题 tokens 独立模块 + 应急登录 + **手动**成员 CRUD + 导出 | **浏览器里立刻有界面**；换肤只改 tokens |
| **P0-ocr** | 截图上传 → OCR/版面解析 → 预览确认 → 按角色名新增/更新 | 管理端「从截图导入」可用 |
| **P0-c** | 扫码登录（管理员微信）完善；角色校验收紧 | 管理端登录更贴近定稿 |
| **P0-d** | `miniprogram`：主题 tokens + 登录绑定 + 成员列表只读 | 手机/模拟器看评分 |
| **P0-e** | 邀请码入会闭环（若未在 b 做完） | 申请→审核→可看成员列表 |

原则：管理端录入是数据源头；**先手录后 OCR**；小程序最后。主题从 P0-b 第一天就抽离，禁止写死色值。

### 交付（按子阶段勾选）

- [x] P0-a：云开发与成员写接口骨架（本地 `dev-server`；云函数/云库适配已就绪，待导入验收）
- [x] P0-b：PC 主题 tokens + 手动成员 CRUD + 超管应急登录 + 导出
- [x] P0-ocr：俱乐部成员页截图识别导入/更新（含确认预览；RapidOCR 优先 / Tesseract 兜底）
- [x] P0-c：管理端微信扫码登录（2026-10-22 验收；票号确认可用，openid 须用复制结果）
- [x] P0-d：小程序成员列表只读（含小程序侧 tokens + 角色名绑定；2026-10-22 验收；见 `docs/P0-d成员端.md`）
- [x] P0-e：邀请码关联已有成员（角色名须匹配名单；审核只绑微信；移出解绑；见 `docs/P0-e邀请码入会.md`）
- [x] 成员字段：角色名（唯一）、等级、非凡评分、风尚度、序列/途径、职位、备注（全员可见）

### 验收

1. **中期（P0-b）**：管理员在 PC 网页**手动**增改成员与评分；改 tokens 可改变整体配色而不改业务页。  
2. **中期（P0-ocr）**：上传游戏俱乐部成员截图，确认后能批量新增/更新。  
3. **完整 P0**：小程序已入会成员能看到同一数据；未入会仅能走邀请码申请。

### 预估工作量（参考）

约 1～2 周；其中 **P0-a + P0-b 优先**，便于尽早在网页验收。

- [x] 列表带回 `accountRole`；未关联不可任命

## 同步 GitHub

本地 Git 就绪后，在 GitHub 新建空仓库，于本仓库根目录：

```bash
git remote add origin <仓库 HTTPS 或 SSH URL>
git branch -M main
git push -u origin main
```

勿将 `.env`、密钥、`project.private.config.json` 等提交入库（见根目录 `.gitignore`）。
