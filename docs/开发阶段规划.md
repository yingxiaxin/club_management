# 开发阶段规划

## 总原则

按 **P0 → P1 → P2 → P3** 严格递进；每一阶段有可验收的「能用」产物，避免并行堆砌组队导致 MVP 延期。

技术落地默认：`miniprogram/` + `admin/` + `cloud/`（微信云开发）。

---

## P0 — MVP：成员可录入、可查看

**目标**：管理员维护花名册；成员打开小程序能看到评分等信息。

### 交付

- [ ] 云开发环境与三端目录可运行骨架
- [ ] 角色：超管 / 管理员 / 成员 / 访客
- [ ] 小程序微信登录 + 绑定档案
- [ ] 邀请码入会申请 + 后台审核
- [ ] 成员字段：角色名（唯一）、非凡评分、风尚度、序列/途径、职位、备注（全员可见）
- [ ] 小程序花名册列表/详情（排序、筛选）
- [ ] PC 后台：扫码登录、成员 CRUD、批量改评分、导出、邀请码
- [ ] 超管应急账号登录入口（最小可用）
- [ ] 首页/公告可为占位

### 验收

管理员改评分后，已入会成员刷新小程序即可看到最新数据；未入会用户只能走邀请码申请。

### 预估工作量（参考）

约 1～2 周（视熟悉云开发程度；AI 辅助编码可压缩）。

---

## P1 — 活动防遗忘：日程 + RSVP + 提醒

**目标**：今日/本周活动清晰；能表态参加/请假；关键活动可微信提醒。

### 交付

- [ ] 活动模板 + 活动实例 CRUD
- [ ] 小程序：今日/本周活动、详情
- [ ] RSVP：参加 / 待定 / 请假
- [ ] 管理员配置默认提醒提前量；活动可覆盖
- [ ] 「提醒我」订阅授权 + 定时发送云函数
- [ ] 公告与俱乐部图标等资料
- [ ] 活动详情预留「组队」入口（可先跳转空态）

### 验收

管理员发布本周活动后，成员能看到并 RSVP；完成订阅的成员在配置的提前量收到提醒（或开发阶段用测试模板验证链路）。

---

## P2 — 组队 LFG

**目标**：副本/PVP 可建队招人，审批制，与活动打通。

### 交付

- [ ] 创建队伍、申请、队长审批、满人关闭、未满再开
- [ ] 踢人、转让队长
- [ ] 活动开始自动结束招募
- [ ] 筛选：今晚/本周；我创建的/我参加的
- [ ] 后台队伍总览（查看、必要时强制关闭）

### 验收

围绕一场已发布活动，完整走通：建队 → 申请 → 通过 → 满员 → 到点结束。

---

## P3 — 运营打磨

**目标**：更好管活跃与责任追溯，不挡主路径。

### 交付（按需裁剪）

- [ ] 简易出勤（活动 RSVP 实到/参与次数可先做统计版）
- [ ] 成员「本周请假」状态
- [ ] 评分变更简史
- [ ] 管理员操作审计日志
- [ ] 超管「重置业务数据」完整流程与二次确认
- [ ] 体验与文案打磨

---

## 建议实施顺序（单周视角示例）

| 顺序 | 内容 |
|------|------|
| 1 | 仓库与云环境、集合权限、登录与角色 |
| 2 | 成员模型 + 后台 CRUD + 小程序列表 |
| 3 | 邀请码与审核闭环 |
| 4 | 导出与应急登录 |
| 5 | 进入 P1 活动域 |

## 同步 GitHub

本地 Git 就绪后，在 GitHub 新建空仓库，于本仓库根目录：

```bash
git remote add origin <仓库 HTTPS 或 SSH URL>
git branch -M main
git push -u origin main
```

勿将 `.env`、密钥、`project.private.config.json` 等提交入库（见根目录 `.gitignore`）。
