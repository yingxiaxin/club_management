## 1. 产品目标

解决两类痛点：

1. **成员战力不清**：集中维护并展示非凡评分、风尚度、序列/途径等。
2. **活动容易忘记**：今日/本周活动可见，支持出席意向（RSVP）与可配置的微信订阅提醒；并与组队招募打通。
3. **氛围与晒图（踏云寻芳）**：成员分享游戏风景/角色自拍与简介（P2 组队之后交付）。
4. **运营可看、个人可查（P3）**：管理端今日/本周出勤看板与轻量实到；成员「我的」聚合 RSVP/队伍（不挡正式公开）。  
5. **周活跃触达（P4）**：首页「本周会务」摘要（我的 RSVP / 我的队伍缺口 / 待处理）；不挡正式公开。

## 2. 角色与权限

| 角色 | 标识 | 能力摘要 |
|------|------|----------|
| 超管 | `super_admin` | 全部管理员能力 + **指定/撤销管理员** + **危险操作：重置俱乐部业务数据** + 应急账号管理 |
| 管理员 | `admin` | 成员 CRUD、评分/风尚度更新、邀请码、活动、公告、俱乐部资料（图标等）、提醒配置、数据导出、入会/部分运营审核；踏云寻芳阶段含**晒图总览与用量、删帖**；P3 含**出勤看板、实到点名**；**不可**任命其他管理员 |
| 成员 | `member` | 查看成员列表与备注、查看活动与公告、RSVP、订阅提醒、创建/加入队伍、队长侧审批/踢人/转让；**踏云寻芳**发帖/浏览；**我的**（身份/RSVP/队伍等，见 §3.9） |
| 访客 | `guest` | 仅可填邀请码发起入会申请（通过前不可看成员列表与活动细节） |

**任命管理员（v1.3）**

- 仅超管；入口在管理端**成员列表**；目标必须已有 `boundOpenid`（邀请码关联完成）。  
- 任命：`users.role = admin`（可扫码进管理端）；撤销：降为 `member`（保留微信关联与小程序成员能力）。  
- 不在此流程创建/撤销 `super_admin`；与游戏「职位」字段无关。  
- 详细规则与验收：`docs/任命管理员.md`。

### 2.1 登录方式

| 端 | 方式 |
|----|------|
| 微信小程序 | 微信登录；openid 绑定成员档案（P0-e：邀请码 + 角色名与名单匹配后关联；未关联不可看名单） |

## 3. 功能模块详述

### 3.1 成员列表（P0）

**字段（成员档案）**

| 字段 | 必填 | 说明 |
|------|------|------|
| 角色名 | 是 | **全俱乐部唯一**；不作游戏数字 ID |
| 等级 | 否 | 游戏角色等级；手录或截图识别（若图中有） |
| 非凡评分 | 是 | 游戏内官方战力；手录或截图识别 |
| 风尚度 | 是 | 手录或截图识别（若图中有） |
| 序列/途径 | 是 | 文本或枚举；手录或截图识别（若图中有） |
| 职位 | 是 | 如会长/副会长/骨干/成员等；手录或截图识别（若图中有） |
| 备注 | 否 | **全员可见** |
| 入会时间 | 系统 | 审核通过时间 |
| 状态 | 系统 | 待审核 / 正常 / 已退出；**仅管理端手动移出**标为已退出（同时解除微信关联：清 `boundOpenid` / `users.memberId`，普通成员降为访客）；截图/批量导入或**手录新增同名已退出**时一律恢复为正常 |
| 最近识别来源 | 系统 | 可选：记录最近一次 OCR 任务，便于追溯 |

**能力**

- 小程序：列表（排序：评分/风尚度/入会时间；筛选：途径、职位）；详情看全部字段；成员列表/队伍队员行与管理端同款**途径渐变**（细原色条 → muted → 透明）；凡展示**角色名**处用途径色（含详情大标题、会务条/「我的」、RSVP 色签、队伍队长名、踏云作者名等；无途径则默认色）。
- 后台：增删改查、批量改评分/风尚度、导出 Excel/CSV；成员表用途径**色签** + 行渐变（3px 原色条 → muted → 行尾透明）区分；列表**途径筛选为下拉多选**（观众/战士/歌颂/学徒/占卜/窥秘/未填写，可多选）。
- **成员录入两种方式（均在 PC 管理端）**：
  1. **手动录入 / 编辑**表单（序列/途径为**单选下拉**：观众/战士/歌颂/学徒/占卜/窥秘，可清空）。手录「新增」时若角色名已在职 → 提示已存在；若仅有**已退出**同名档案 → **恢复在职并更新表单字段**（与截图导入一致；云库 `characterName` 唯一索引含已退出）。
  2. **截图识别**：在游戏内打开俱乐部成员列表页 → 截图上传 → 系统 OCR/版面解析 → 给出识别结果预览 → 管理员确认后 **新增或按角色名更新**。
- 评分无额外查看权限（全员可看）。

**截图识别规则（产品）**

- 匹配键：**角色名**（唯一；无游戏数字 ID）。已存在（含已退出）则更新评分等字段并**恢复为正常在职**；不存在则新建（职位等缺省可用默认「成员」）。
- 必须有 **人工确认步**：不可静默覆盖；预览表可勾选行、可改字段后再提交。
- 支持多图连续上传（长列表翻页多张截图）；管理端支持 **选择文件 / 拖拽 / 剪贴板粘贴**（`Ctrl+V`，粘贴后自动识别）。
- 识别失败或置信度低时标红，引导改用手改。
- 实现依赖通用 OCR + 针对「诡秘之主俱乐部成员列表」版面的解析；游戏 UI 改版时可能要调解析逻辑（非官方 API）。
- **实现备注（P0-ocr / 本地）**：引擎优先级为 **腾讯云（可选）→ RapidOCR（本机 Python `rapidocr_onnxruntime`）→ Tesseract**。RapidOCR 使用坐标版面解析，角色名/等级/评分通常较准；Tesseract 兜底时角色名仍易受头像遮挡。确认表可编辑，导入前请扫一眼。配置见 `cloud/dev-server/.env.example` 与 `cloud/dev-server/README.md`。
- **实现备注（云库）**：成员可存微信云开发 `members` 集合；管理端经本地 API 在 `DATA_BACKEND=cloud` 时读写云库。导入步骤见 `docs/云数据库接入.md`。

**入会 / 微信关联（P0-e）**

成员档案仍由管理员手录或截图导入；邀请码**不创建新成员**，只把微信与已有角色关联，避免无关人看到俱乐部信息。

1. 管理员生成邀请码（可设有效期、次数上限），发给真实成员。  
2. 访客输入邀请码 + **角色名**（须与名单完全一致）→ 提交关联申请。  
3. 角色名不在名单 / 已被他人绑定 → **直接拒绝**，不可提交。  
4. 管理员通过/拒绝；通过后写入 `boundOpenid` 与 `users.memberId`，申请人可看成员列表。  
- **实现备注**：管理端 `/invites`；小程序 `pages/join`；见 `docs/P0-e邀请码入会.md`。

- 配色、字号、圆角、间距等须抽成 **独立主题模块**（如 Design Tokens / CSS 变量），业务页面不写死色值。

### 3.3 活动日程与 RSVP（P1）

**活动字段**

| 字段 | 说明 |
|------|------|
| 标题 | |
| 类型 | 日常 / 周本 / PVP / 自定义（创建时直接选择，无独立模板） |
| 开始 | 分量：年月日 / 时间 / 星期（至少填一项）；完整年月日+时间可落到绝对时刻；管理端可「填入今天」（年月日+星期，不改时间） |
| 结束 | 同开始，可选；亦可「填入今天」 |
| 开启提醒 | 管理端新建/编辑为**开关**；关则不发。开则按开始分量自动定周期（有完整年月日→一次；有周几→每周；有日→每天；仅时间→每天）；**须有开始时间**才可开 |
| 提醒提前量 | **一律**用俱乐部「提醒设置」中的提前量；活动上不再单独配置 |
| 说明 | |
| 是否开启组队 | 开启则详情页展示队伍入口；**新建默认开** |
| 状态 | 草稿 / 已发布 / 进行中 / 已结束 / 已取消。**一次性**（锚定具体开始日时）本场结束后由定时/读路径自动 → 已结束，并关闭下属仍在招募的队伍；**周期模板**（仅周几/每日等）保持已发布，仅换场清 RSVP+队伍 |

**展示**

- 活动页：**今日活动**、**本周活动**；首页会务条嵌入**本日/本周活动**（不再单独「今日活动」区块）。
- 详情：说明、时间、RSVP 汇总、队伍列表入口（若开启组队）。
- 开启组队时：**整块组队区**点击进入本活动队伍列表（不再单独「查看」按钮）；「创建」仍可一键进创建页。
- **次级页回首页**：非 Tab 页（详情/组队/入会等）右下角浮动小房子图标 → `switchTab` 回首页；Tab 三页不显示。

**RSVP（出席意向）**

| 状态 | 含义 |
|------|------|
| `going` | 参加 |
| `maybe` | 待定 |
| `decline` | 请假 |

- **可改时机**：活动为 `published` / `ongoing` 时，**已开始仍可表态**；按**本场结束时间**锁定——已结束则不可报名（无结束分量时默认该场开始日当天 23:59 上海时区）。`ended` / `cancelled` 不可表态。
- **周期模板**（仅周几/每日等）：列表与详情须标注**本场具体日期**（如 `10月23日 周五 09:30`）；本场结束后清空该活动下全部 RSVP 与队伍，并滚动展示**下一场日期**；当日已结束的场次仍可出现在今日/本周列表，但排在最后。
- 列表展示各状态人数与名单；名单 label 按成员**途径色**着色（见视觉指南）。
- **管理端导出（意向）**：活动日程「导出 RSVP」→ 可选**本场**或某一**场次日**（周期换场前自动快照）下载 CSV（角色名、途径、状态、活动时间）。见 `docs/P1-c出席意向RSVP.md`。不做快照列表页。  
- **管理端导出（点名）**：出勤看板点名抽屉「导出点名表」→ CSV（角色名、途径、RSVP、实到、场次日）；按抽屉**当前勾选**导出（可与未保存勾选一致）；与上项意向导出并存，见 `docs/P3出勤与个人中心.md`。

**列表排序**：今日 / 本周列表中，**本场已结束**的活动排在未结束之后，其余仍按开始时刻等规则。

**本场阶段（列表展示）**：按开始/结束时刻标 **未开始 / 进行中 / 已结束**（与云库 `status` 草稿·已发布等管理态区分；首页与活动页均展示）。

### 3.4 订阅消息提醒（P1）

- **管理员在「提醒设置」配置**提前量：5 / 10 / 15 / 30 分钟、1 / 2 小时（可多选，产品默认 **10 分钟**）及模板 ID、下发环境。
- 活动侧仅「开启提醒」开关；**提前量不按活动覆盖**，一律跟提醒设置。
- 成员在活动详情点击「提醒我」完成订阅授权后，到点由云函数发送订阅消息。
- 约束（微信平台）：未授权无法推送；模板需过审；不宜高频骚扰。

### 3.5 活动组队 LFG（P2）

> **实现约定**：`docs/P2组队.md`（正式公开前必做）。

**队伍字段**

| 字段 | 说明 |
|------|------|
| 关联活动 | 必填（与活动打通）；活动须 `enableTeam` |
| 副本/模式 | 文本 |
| 开打时间 | 队伍自有绝对时刻 `startAt`；创建时默认复制活动 `startAt`（若有），可改；**到点以此为准** |
| 人数上限 | ≥ 2；创建默认 **6** |
| 要求评分 | 最低非凡评分，可选；不足则不可申请 |
| 备注 | |
| 队长 | 创建者；可转让 |
| 状态 | 招募中 / 已满员 / 已关招募（可再开） / 已开始 / 已撤销（列表不显示） |

**规则**

1. 成员创建队伍 → 状态「招募中」。
2. 他人申请加入 → **队长审批**（通过/拒绝）。
3. 人数达上限 → 自动「已满员」，关闭新申请；有人退出且未满 → 回到「招募中」。
4. 队长可踢人、可转让队长；可**关闭招募**（他人不可再申请，可再开）或**撤销队伍**（解散且列表不再显示）。
5. **到达队伍 `startAt`** → 自动结束招募（「已开始」）；无 `startAt` 则不自动。
6. 同一活动同一成员最多加入一支队伍；筛选：今天 / 本周；「我创建的」「我参加的」（无队伍开打时间时按活动本场日期）。
7. 入口：活动详情（开启组队时）；不做独立组队 Tab。

**申请状态**：待审批 / 已通过 / 已拒绝 / 已取消 / 被踢出。

### 3.8 出勤看板（P3）

> **实现约定**：`docs/P3出勤与个人中心.md`。不挡正式公开；按刀点名开发。

**管理端「出勤看板」**（侧栏，建议在活动日程下）

| 子视图 | 说明 |
|--------|------|
| 今日一屏 | 上海「今天」本场活动；RSVP 三态人数；开启组队时嵌今日该活动队伍摘要（非 P2-e 总览） |
| 本周概览 | 本周各活动 RSVP 汇总；已点名则显示实到人数 |
| 成员出勤摘要 | 近 4 周 going/decline 次数；可下钻近 N 场 |

**实到（轻量）**：管理员对已结束场次勾选实到（进行中可预勾）；默认预勾 `going`；存 `activity_attendance`，**不改** RSVP。不做成员自助/扫码签到。点名抽屉可**导出点名表**（RSVP + 实到）；活动日程仍保留「导出 RSVP」意向表。

**本周请假**：已砍（与单场 RSVP `decline` 重复）；不做周级开关与 `member_week_leave`。

**统计口径**：意向出勤率分母=该成员有过 RSVP 的已结束场次数；实到率=`实到人数/点名时 going 人数`。不做积分与全员排行榜公示。

## 5. 状态机（摘要）

### 5.1 入会申请

`pending` → `approved` | `rejected`

### 5.2 活动

`draft` → `published` → `ongoing` → `ended`；任意已发布后可 `cancelled`。  
一次性：本场结束时刻到点自动 `ended`（关闭招募中队伍）。周期：可长期 `published`，本场结束只换场不清「已发布」。

### 5.3 队伍

`recruiting` ⇄ `full` ⇄ `paused`（关/开招募）；可 `dissolved`（撤销）；到点 → `started`

### 5.4 入队申请

`pending` → `approved` | `rejected`；成员可 `cancelled`；队长可致 `kicked`

## 6. 非功能需求

- 规模：100～200 成员，读写以管理员更新评分与成员浏览为主。
- 安全：管理端接口校验角色；危险操作二次确认；密钥不进仓库。
- 导出：成员列表 CSV；活动 RSVP 按活动 CSV（见 §3.3）。
- 明确不做：语音、积分商城、陪玩订单、DKP、**游戏官方 API 自动同步**、多租户；P3 出勤不做全员排行榜公示与成员自助签到。  
  （截图 OCR 属于人工辅助录入，允许做。）
- 主题：样式可独立替换，见 §3.1.1。
